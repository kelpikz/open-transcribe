# Porting brief — Python → TypeScript

Read this fully before writing code. It carries findings that were expensive
to establish; rediscovering them costs hours.

## Ground truth you must not relitigate

**The live endpoint is dead.** `POST https://chatgpt.com/backend-api/codex/realtime/calls`
returns `404 {"detail":"Not Found"}` as of 2026-08-14. This is *not* an auth
problem — the same token returns `200` on `/backend-api/me`, `/accounts/check/v4-2023-04-27`
and `/models`, and `/codex/responses` returns a Codex-specific `400`. Nine path
variants were probed; all 404.

The decision has been made deliberately: **port faithfully anyway, fix the
endpoint later.** Do not redesign around a different transport, do not try to
find the new endpoint, do not "improve" the protocol. Port what is there.

Consequence: `negotiate()` and anything downstream of it cannot be verified
against the service. Do not write tests that hit the network. Test the
request *construction* and the event *handling*, which is where port
regressions actually live.

## Rules

1. **Faithful transliteration.** Same functions, same names, same behaviour,
   same edge cases — including ones that look like bugs. If the Python
   swallows an exception, swallow it. If it truncates to 110 characters,
   truncate to 110. Preserve behaviour first; note anything suspect in your
   final report rather than fixing it.
2. **No Effect.** Plain TypeScript. Use `await using` / `AsyncDisposable` for
   resource cleanup and `AbortSignal` for cancellation where the Python used
   `try/finally`. Effect may be adopted later; keep the seams clean.
3. **Runtime-agnostic core.** `auth.ts` and `realtime.ts` must use only
   standard APIs — `fetch`, `crypto`, `atob`, `TextDecoder`, `node:fs`. **No
   `Bun.*` anywhere in them.** The desktop app will run these under Electron's
   Node, and every `Bun.file` becomes a rewrite. Bun-specific code belongs in
   `audio.ts` and `cli.ts` only.
4. **Match the fixtures exactly**, including snake_case field names. The
   fixtures are the oracle; TS naming convention loses to them.
5. **Types live in `src/contract.ts`.** Import from there. If you need a new
   shared type, add it there and say so in your report — do not duplicate it
   locally.

## The oracle

`fixtures/*.json` records the Python's exact output, generated by
`tools/gen_fixtures.py`. The live service is gone, so this is the only record
of how the tool behaves. Your TS tests must assert against these files.

| Fixture | Covers |
|---|---|
| `build_session.json` | 12 argument combinations → exact payload |
| `realtime_constants.json` | every module constant, both event-name sets |
| `jwt_exp.json` | 10 tokens incl. unpadded base64, numeric strings, garbage |
| `auth_headers.json` | header minting across auth shapes |

| `transcript_text.json` | joining, stripping, blank-dropping, unicode |

## Findings that change how you write the code

**werift works under Bun.** Verified: `RTCPeerConnection` produces a complete
offer with an Opus audio m-line, an `application` m-line for the data channel,
`a=end-of-candidates`, and `iceGatheringState: "complete"` after
`setLocalDescription` — matching aiortc's non-trickle behaviour, so
`pc.localDescription.sdp` is ready to POST exactly as the Python assumes.

**werift's track takes RTP, not PCM.** This is the single biggest structural
divergence from the Python. `MediaStreamTrack.writeRtp(rtp: RtpPacket | Buffer)`.
aiortc accepted PCM `AudioFrame`s and did Opus encoding *and* RTP
packetization internally; werift does neither. The audio module must produce
encoded Opus in RTP packets.

Recommended route: one `ffmpeg` process does capture, resampling, and Opus
encoding, with `-f rtp` writing to a local UDP socket that you read via
`node:dgram` and forward to `writeRtp`. ffmpeg then owns packetization and
pacing, which is also what makes file playback run at realtime rather than
blasting a one-hour file at the server in seconds. Alternatives (Ogg-Opus
parsing, `@discordjs/opus`) are acceptable if better — justify in your report.

**One known behavioural difference to note, not fix:** werift gathers `srflx`
candidates via a default STUN server; aiortc gathers host candidates only.
Record it in your report; do not chase it.

## Workflow (per module)

1. Write pytest tests for your Python module. Run them; make them pass. If a
   test fails because the Python is wrong, **do not fix the Python** — record
   the actual behaviour, since that is what the port must reproduce.
2. Commit.
3. Mirror those tests into `ts/tests/<module>.test.ts` (`bun test`), asserting
   against the same fixtures.
4. Write `ts/src/<module>.ts`.
5. Make the tests pass. Run `bunx tsc --noEmit` — it must be clean under
   `strict` and `noUncheckedIndexedAccess`.
6. Commit.
7. Spawn an adversarial reviewer subagent. Iterate until it has no findings.
8. Commit.

Do **not** delete any Python — that happens once at the end, centrally.

## Reporting back

State: what you ported, which fixtures you assert against, test and typecheck
results (actual output, not a claim), any behavioural divergence from the
Python and why, anything you added to `contract.ts`, and anything you think is
a latent bug that you preserved rather than fixed.
